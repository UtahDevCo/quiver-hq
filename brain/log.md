# Bundle history

## 2026-07-29 (promotions from the corroboration pass)

- **Promoted [authorize-before-doing-work](meta/practices/authorize-before-doing-work.md)** — wiley calls `assertSelfOrAdmin()` before any Firestore read, trikin calls `checkAdminAuthorization()` first in every admin action. Two unrelated stacks, two auth models, and *neither repo documents the rule* — the codebases just do it everywhere. A convention followed without being written down is usually stronger evidence than one that had to be. The concept keeps the ordering subtlety: validation may precede authorization when you need a parsed input to know what you're authorizing against; no read, write, or external call may.
- **Promoted [kebab-case-files-named-exports](meta/practices/kebab-case-files-named-exports.md)** — independent code evidence in all four repos. Recorded with the *reason* the no-default-export half is load-bearing rather than as taste: the import name becomes part of the contract, barrels stay mechanical, and rename-symbol keeps working. Names the Next.js `page`/`layout`/`route` requirement as a framework contract, not a violation, so nobody "fixes" it.
- **Promoted [corroboration-requires-independent-sources](meta/workflows/corroboration-requires-independent-sources.md)** into the previously empty `meta/workflows/`. This is the methodology lesson from this session's near-miss, with the one-line `grep -Fxf` check that catches it and an explicit evidence ranking. Also records the inverse error: absence is not disagreement, so *unfalsifiable here* must be reported separately from *contradicted here*.
- **Kept `mock-at-narrowest-scope` in meta, with the evidence stated plainly.** `tools` tests but never mocks, trikin showed no mock setup, wiley has no test files at all. That is absence of evidence, not disagreement, so it stays default-on — the cost of following it in a repo with no mocks is zero. The concept now says which half generalizes (assert `toHaveBeenCalledWith` *and* `toHaveBeenCalledTimes`) and which half is runner-specific, plus the condition for demoting it later.
- **Wrote up wiley's drawer stack after reading the container**, which had been the outstanding coverage gap. The genuinely copyable ideas: controlled-or-uncontrolled via `open ?? isInternalOpen` with callbacks firing either way; a 175ms debounce keeping the node mounted past close so the exit animation runs without an unmount flash; push mode measured once with `getBoundingClientRect()` then handed to CSS via a custom property; and a reference-counted scroll lock keyed by `useId` that survives nested drawers.
- **`useDrawerState` is the best artifact in wiley's UI layer** and it isn't the drawer. It takes `pathname`, `searchParams`, and `handleReplace` as *parameters* — zero framework imports in a hook whose whole job is URL manipulation — so it unit-tests with a `URLSearchParams` and a spy instead of a mounted app. It also deletes the mode param when it equals the default and no-ops when serialization is unchanged, which are the two things this pattern usually gets wrong.
- **Recorded the drawer's rough edges rather than only its strengths**: `closeHighestDrawer()` routes control flow through a simulated DOM click on a CSS class; one Escape press fires once per open drawer; module-level mutable counters sit beside the `Map`-based reference counting that supersedes them; the `id` prop is accepted and explicitly ignored while `useDrawerState`'s `id` is the one that matters; and the trigger wrapper is a bare `<div onClick>` in an otherwise a11y-careful component. A pattern doc that lists only strengths is marketing.
- **Flagged an unresolved duplication**: wiley has both `components/shared/drawer.tsx` (custom, framer-motion, 4 consumers) and `components/ui/drawer.tsx` (shadcn over `vaul`, 1 consumer). Two interchangeable options coexisting is what [make-misuse-unrepresentable](meta/practices/make-misuse-unrepresentable.md) says to resolve by deletion. Not acted on — the brain describes and does not retrofit — but noted as the cheap cleanup for whoever next touches that billing page.
- **Recorded what was examined and deliberately not kept** in wiley's index: `sidebar.tsx` is genuinely not portable (hardwired nav, PostHog, `useUser`), `header.tsx` is portable but trivial, and `data-table.tsx` is portable only if you adopt TanStack *and* own the query state in the parent. Silent omission would read as coverage.
- **Meta index 85 → 90 lines**, 24 concepts. Two previously empty sections (`Workflows`, and `Practices — security`) now have content.

## 2026-07-29 (corroboration pass)

- **Harvested `tools`, `trikin`, and `wiley`** read-only, to test the 19 meta practices and patterns that rested on zamp alone. Fan-out on reading, classification kept central — deciding whether something is corroborated requires seeing all repos at once, which no per-repo agent can do.
- **Discovered the corroboration method was partly invalid, and corrected for it.** `trikin/AGENTS.md` shares **59 of its 118 non-blank lines byte-identically** with `tools/AGENTS.md`, and the shared block opens `Auto-generated from all feature plans`. They descend from a common template, so any rule appearing only in both is *one document counted twice*. Everything was re-scored on independent **code** evidence only. Without this check, roughly a dozen shared-template rules would have been promoted as cross-repo agreement.
- **Seven practices confirmed by independent code evidence in all three repos** and no longer single-source: `follow-local-conventions`, `minimal-comments`, `small-single-purpose-files`, `error-propagation-and-capture`, `no-error-objects-across-boundaries`, `colocate-schemas-with-what-they-validate`, `ds-wrapper-passthrough`.
- **Enriched `no-error-objects-across-boundaries`** with two independent derivations. `trikin` reaches the same rule from unrelated physics — across a Cloudflare Worker `fetch` boundary `Error` instances and `instanceof` don't survive at all, so everything crosses as `{ success, error?: string }`. `wiley` reaches it a third way as a repeated action-boundary idiom. Three repos, three different reasons; this is now the best-evidenced practice in the brain.
- **Refined `colocate-schemas-with-what-they-validate`**: the *adjacency* is universal, the *filename convention* is not. zamp uses `*.schema.ts`, wiley a feature-local `schemas/` directory, trikin `types.ts`. wiley's directory looks like the centralization the practice warns against and isn't — it sits inside the feature beside its consumers. The test is distance to the consumer, not the path spelling.
- **`directive-driven-filenames` will not be promoted.** This was the open question from the previous batch. Wiley is also Next.js but encodes runtime context by **directory** (`app/actions/`, `"use client"` inline, semantic filenames), not by suffix. The principle corroborates; zamp's `*.client.tsx` / `*.action.ts` mechanism does not. Stays at the zamp layer, and the promotion note has served its purpose.
- **Narrowed `typography-and-layout-as-utilities` and created the bundle's first `Practice Override`.** `tools/packages/components/src/typography.tsx` is a deliberate `Typography` component with purpose-named variants — a direct counterexample to the "no `Text`/`Heading`" prohibition. On Chris's ruling the prohibition became a zamp `mode: extend` override; the positive guidance (purpose-named font utilities, semantic elements, `gap` over margins) stayed meta, with `gap`-over-margins now independently corroborated. A repo using a typography component is no longer deviating from anything.
- **Demoted two patterns to `projects/zamp/patterns/` on Chris's ruling** that both are zamp standards: `theme-by-data-attribute` (both other repos theme by **class** selector, not `[data-theme]`, and neither uses folder-per-theme) and `accessibility-enforced-by-types` (neither implements the union; both expose an optional `aria-label`, which is precisely the weaker alternative the pattern exists to replace — scoring them as corroboration would have been backwards). Each records the demotion reasoning in its own body, and `meta/patterns/index.md` keeps pointers so the old paths stay explicable.
- **This refines the earlier blanket assertion** that zamp's design-system standards are Chris's standard everywhere. The token architecture and wrapper layering hold — and are now corroborated by `tools` and `wiley` on merit rather than on assertion. The component-level *prohibitions* are zamp's alone. Worth knowing that the assertion was right about the layer it was really about.
- **Side effect on `make-misuse-unrepresentable`**: one of the two instances it was synthesized from is now a zamp-layer pattern, so the brain's only non-source-traceable concept rests on one meta instance plus one project instance. Still the weakest link, now weaker.
- **Coverage, stated plainly.** wiley has **no test files**, so the two testing practices are unfalsifiable there rather than corroborated. `trikin` has no design system, making 6 of the 19 structurally unanswerable. The wiley `Drawer` *container* was not read, only its consumer. Effective corroboration on design-system practices is 2 repos, not 3.
- **Still single-source and now the brain's weakest claims**: `mock-at-narrowest-scope` (no mocks in `tools`, no tests in wiley), `deprecate-without-breaking-consumers`, `conventional-comments` (about review output, so code evidence cannot falsify it), and `make-misuse-unrepresentable`.
- **Meta index back to 85 lines** — the two demotions paid for the four failure modes.
